## 性能样本

本机参考样本为 2,000 条笔记，每条正文约 2 KiB；组合全文搜索、颜色及标签筛选 7 次，中位数 **0.49 ms**。`tests/performance.test.ts` 以中位数小于 100 ms 作为本机回归目标。这是纯筛选函数的合成测量，不代表端到端渲染时间或其他设备性能。

首页每次最多渲染 100 张卡片，使用“加载更多”；Milkdown 在打开笔记时按需加载。输入包含编辑器序列化与本地防抖，300 ms 保存反馈仍需在目标手机和较慢存储设备上实测。构建的主入口约 805 KiB（gzip 约 252 KiB），编辑器延迟 chunk 约 357 KiB（gzip 约 109 KiB）；构建会提示主入口超过 500 KiB，后续可继续拆分加载。

## 真实 GitHub 验收

通过实际 Chromium 页面连接专用私人仓库 [scarletkc/Tebikae-dev](https://github.com/scarletkc/Tebikae-dev)。测试凭证仅在运行进程与浏览器内存中使用，未启用带凭证的 trace。

- 初次连接只发读取请求，没有创建 Issue。
- 从界面创建 `tebikae-acceptance` 标签。
- 创建中文可视化 Markdown 笔记，设置绿色并添加标签；随后独立调用 GitHub GET 核对标题、正文、颜色与标签。
- 执行归档、移入回收站、恢复；独立 GET 确认恢复后仍是 closed 归档状态，正文和标签保留。
- 刷新后 Token 输入为空，主动打开缓存后仍可阅读该归档笔记。
- 检查 IndexedDB、localStorage、sessionStorage 和请求目标，没有发现 Token 持久化或发往其他主机。

测试记录保留为已归档的 [Issue #1](https://github.com/scarletkc/Tebikae-dev/issues/1)，未永久删除内容。可复现脚本为 `scripts/test-live.mjs`；本次结果原件位于本地 `.artifacts/live-acceptance.json`，不作为包含私人测试数据的公开构建产物。

本次使用已有 GitHub CLI 登录凭证，**不能据此证明仅授权单仓库 Issues 读写的 fine-grained PAT 已完成真实验收**。权限最小化依据端点文档与请求范围，仍需用该权限配置的独立 Token 实测。

## 发布前仍需核对

1. Windows／macOS 中文输入法、实体手机软键盘、粘贴长文和输入法撤销体验。
2. iOS／Android 主屏幕安装、飞行模式、系统终止、存储清理和低空间表现。
3. 单仓库最小权限 fine-grained PAT 的真实读写，以及实际失效／撤销权限场景。
4. 选定托管平台上的 HTTPS、响应头、CSP、不同资源集合的版本更新与回滚。

自动化和本地真实 API 验证已经完成；以上项目需要对应设备、凭证或正式站点环境。GitHub Issue 接口没有原子条件写入保证，跨设备检查后写入的竞争窗口仍存在；产品按个人笔记的最终一致性设计。
